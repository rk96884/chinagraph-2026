Engineering principles

The principles behind my work

These principles guide how I approach new features, technical decisions and collaboration throughout a project.

01

Accessibility from the start

Inclusive experiences are easier to create when accessibility is considered during structure, design and development rather than added as a final audit.

02

Progressive enhancement

Begin with clear content and semantic HTML, then layer richer presentation and behaviour without weakening the underlying experience.

03

Component thinking

Reusable patterns reduce duplication, create consistency and make interfaces easier to extend as requirements evolve.

04

Performance matters

Responsive images, efficient assets and sensible loading strategies help keep interfaces fast and usable across different devices and connections.

05

Maintainability over cleverness

Clear, understandable code is usually more valuable than an impressive abstraction that makes future changes harder.

06

Collaboration is engineering

Good solutions emerge through communication with designers, developers, project managers and the people who will ultimately use the product.

Development workflow

From first question to dependable release

A practical, iterative process that keeps users, quality and maintainability in view throughout the build.

  1. 01

    Discover

    Understand the problem

    Clarify the audience, the real need and the desired outcome before deciding what should be built.

    • Users
    • Goals
    • Constraints
  2. 02

    Define

    Plan the simplest route

    Break the work into manageable pieces, expose dependencies and identify the risks that matter.

    • Scope
    • Structure
    • Priorities

    Keep the route clear.

  3. 03

    Create

    Build progressively

    Develop in small, meaningful increments using semantic markup, reusable components and maintainable styles.

    • Components
    • Git
    • Integration
  4. 04

    Refine

    Review while change is cheap

    Review code, design decisions and interactions early enough for feedback to improve the outcome.

    • Feedback
    • Refactoring
    • Collaboration

    Every review teaches something.

  5. 05

    Verify

    Test the experience

    Check behaviour across devices, browsers and interaction methods rather than testing only the ideal path.

    • Accessibility
    • Responsive
    • Performance
  6. 06

    Release

    Ship, observe and improve

    Release carefully, learn from real use and feed those lessons into the next iteration.

    • Deploy
    • Measure
    • Improve

Quality

Quality is designed, not added.

Quality isn't something I check at the end of a project. It's built into every decision—from accessible interfaces and maintainable code to performance, consistency and thoughtful user experiences.

Performance

Fast by default.

Efficient front-end architecture, optimised assets and thoughtful engineering decisions help create experiences that feel responsive from the very first interaction.

Accessibility

Inclusive by design.

Accessibility isn't a feature to add later. Semantic HTML, keyboard navigation and clear visual hierarchy help ensure products work for everyone.

Maintainability

Built to evolve.

Readable code, reusable components and consistent patterns make software easier to improve long after the initial release.

Experience

Engineering beyond the code.

Building software for real users has taught me that successful products aren't just about writing clean code. They're shaped by listening, collaborating, refining and making thoughtful decisions throughout the development process.

01

Real users change your thinking.

The best ideas rarely come from assumptions alone. Watching how people interact with a product often reveals opportunities that no specification could predict.

02

Simple usually wins.

I've learned that maintainable solutions often outperform clever ones. Reducing complexity makes software easier to understand, extend and support long after it has been delivered.

03

Good conversations build better software.

Great products are rarely built in isolation. Working closely with designers, stakeholders and developers leads to better decisions and fewer surprises throughout a project.

04

Small improvements compound.

Continuous refinement has a lasting impact. Small enhancements to usability, performance and accessibility gradually create experiences that feel polished and reliable.

Continuous learning

Staying curious by building

The most valuable learning happens when new concepts are applied to a real product with genuine constraints.

Building Football Tournament Manager allowed me to deepen my React skills while gaining practical experience with ASP.NET Core, REST APIs, Entity Framework Core and relational data.

I also use AI-assisted development to accelerate research, debugging and exploration. Suggestions are reviewed critically, tested and adapted to the existing codebase rather than accepted without understanding.
